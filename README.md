# Прототип отладчика PL/pgSQL на Rust

Консольная программа для отладки функций и процедур PostgreSQL. Rust управляет сеансом через `pldbgapi`, а серверный `plugin_debugger` приостанавливает выполнение PL/pgSQL. Прототип показывает, как отдельный от ORM инструмент может подключиться к базе и управлять отладкой.

## Что можно показать

- Автоматическую остановку `debug_smoke(3)`, изменение `running_total` с `3` на `4` после шага и итоговый результат `8`.
- Текущую строку, стек вызовов, переменные и пошаговое выполнение через `next` и `continue`.
- Установку и удаление точек на строках тела функции, просмотр её текста с номерами строк.
- Проверку существующей функции или процедуры валидатором PL/pgSQL без вызова.
- Вызов функции из программы, отдельного `psql` или другого клиента PostgreSQL.
- Ошибку `P0001` в `debug_failure(3)` с отдельным выводом результата SQL-вызова.

## Как запустить

Нужны установленный PostgreSQL с `psql.exe`, `initdb.exe`, `pg_ctl.exe` и совместимые с его версией `plugin_debugger` и `pldbgapi`. Для запуска готового `.exe` Rust и Cargo не нужны.

1. Открыть `dist\pg-debugger.exe`.
2. Нажать Enter для порта `15439` или ввести порт локального PostgreSQL. Если порт свободен, программа создаст учебный кластер. Если там уже работает PostgreSQL, программа подключится к нему и при необходимости запросит пользователя, базу и пароль.
3. В учебном кластере нажать Enter в меню для быстрого показа. Для ручных шагов выбрать `2`, для вызова из отдельного `psql` — `3`, для примера с ошибкой — `4`.
4. Для проверки или отладки своей функции выбрать `5` или `6` и указать её сигнатуру. Для выхода выбрать `0`.

Учебный кластер хранится в `%LOCALAPPDATA%\pg-debugger\demo-pg<версия PostgreSQL>-<версия программы>`. При выходе программа останавливает только созданный ею сервер; данные остаются. Уже запущенный PostgreSQL она не останавливает.

## Как устроен прототип

```text
Rust ── SQL-команды pldbgapi ──> proxy backend PostgreSQL
                                  │ сеанс отладки
psql / другой клиент ───────────> target backend PostgreSQL
                                  │
                                  ▼
                          PL/pgSQL + plugin_debugger
```

Rust открывает управляющее соединение с PostgreSQL. Второе соединение вызывает функцию или процедуру. `plugin_debugger` останавливает её в серверном процессе, а Rust читает состояние и отправляет команды через `pldbgapi`.

## Текущие границы

- Реализован Step Over; Step Into и управление несколькими одновременными сеансами пока отсутствуют.
- Точки можно ставить на исполняемых операторах. Объявление переменной и `BEGIN` не дают отдельной остановки; при выборе этих строк остановка происходит на первом операторе.
- Валидатор проверяет тело без вызова, но не гарантирует успешное выполнение SQL внутри функции или процедуры.
- Интеграции с Python ORM и машинного протокола пока нет. Для внешнего вызова можно использовать отдельный клиент PostgreSQL.
- Учебный кластер слушает `127.0.0.1` и использует `trust`. В уже работающий сервер программа не устанавливает расширение или функции автоматически.
- Закрытие канала отладки не подтверждает успех SQL. Если программа сама запускает целевой вызов, его результат выводится отдельно.

## Подробная инструкция

Меню автоматически ищет установленный PostgreSQL. Ручные команды ниже приведены для PostgreSQL 17 в `C:\Program Files\PostgreSQL\17`; для другой версии или расположения замените путь.

### Режимы меню

1. Быстрый показ `debug_smoke(3)`: отдельный `psql` запускается автоматически, программа показывает остановку, делает один шаг и выводит результат `8`.
2. Ручная отладка `debug_smoke(3)`: `psql` запускается автоматически; команды отладки вводятся вручную.
3. Ручная отладка с отдельным `psql`: программа ждёт вызова, показанную команду нужно выполнить во втором окне `cmd.exe`.
4. `debug_failure(3)`: пример функции, завершающейся ошибкой `P0001`. Результат SQL выводится отдельно от состояния канала отладки.
5. Проверка функции или процедуры без вызова: укажите сигнатуру, например `public.debug_smoke(integer)`. Программа находит объект в базе, вызывает валидатор PL/pgSQL и печатает тело с номерами строк.
6. Отладка выбранной функции или процедуры: укажите сигнатуру и строку первой остановки; Enter ставит точку на входе. Затем выберите способ вызова: `1` — ввести SQL здесь, `2` — вызвать объект из другого клиента или ORM.

Режимы `1`–`4` работают в учебном кластере программы. При подключении к уже работающему PostgreSQL доступны `5` и `6`; выбранная функция или процедура должна существовать в этой базе.

### Как проверить режим `6`

После запуска учебного кластера введите по очереди:

```text
6
public.debug_smoke(integer)
6
1
SELECT public.debug_smoke(5);
```

Программа остановится перед умножением на строке `6`, когда `running_total=6`. Введите `c` после приглашения `debug>`; результат SQL — `12`.

Для вызова из другого окна выберите `2`. После сообщения `Waiting for another PostgreSQL session to call the target...` вызовите **ту же функцию в той же базе** через `psql` или другой клиент. До команды `c` вызов во втором окне будет ждать.

### Строки и команды отладки

`src` печатает строки тела функции, а не строки всего файла `debug_smoke.sql`. Для тестовой функции они выглядят так:

```text
  2 | DECLARE
  3 |     running_total integer := input_value;
  4 | BEGIN
  5 |     running_total := running_total + 1;
  6 |     running_total := running_total * 2;
  7 |     RETURN running_total;
```

Для начальной строки `3` или `4` программа ставит точку на входе. Плагин не останавливается отдельно на объявлении переменной или `BEGIN`: фактическая остановка происходит перед оператором на строке `5`. `Stopped at` показывает эту позицию из стека; после `n` будет показана строка `6`. Точки дальше по телу срабатывают, только если выполняемый путь достигает их.

| Команда | Действие |
| --- | --- |
| `n` / `next` | Выполнить текущий оператор и остановиться перед следующим, не заходя внутрь вызванной функции. |
| `c` / `continue` | Продолжить до следующей точки или завершения вызова. |
| `v` / `vars` | Показать переменные. |
| `s` / `stack` | Показать стек вызовов. |
| `src` / `source` | Показать тело с номерами строк. |
| `b 6` / `break 6` | Добавить точку на строке `6` текущей функции. |
| `d 6` / `drop 6` | Удалить эту точку. |
| `bl` / `breakpoints` | Показать установленные точки. |
| `h` / `help` | Показать команды. |

Точка `b 4`, добавленная после первой остановки на строке `5`, не сработает в текущем вызове: вход в блок уже пройден. Для следующей остановки в тестовой функции введите `b 6`, затем `c`.

## Что проверяет режим `5`

Режим `5` работает с функцией, **уже созданной в выбранной базе**. По сигнатуре PostgreSQL находит запись в `pg_proc`; программа читает её `oid`, язык и текст `prosrc`, а затем вызывает `plpgsql_validator(oid)`. Исходный `.sql` файл из папки проекта этот режим не открывает. Валидатор проверяет определение без выполнения функции, но не доказывает, что запросы внутри неё выполнятся без ошибок на реальных данных.

Учебные объекты программа создаёт из `debug_smoke.sql` и `debug_failure.sql` только в собственном кластере. В обычной базе можно выбрать любую существующую PL/pgSQL-функцию или процедуру, если есть необходимые права и компоненты отладки. Программа подключается к `127.0.0.1` на выбранном порту; для функции в другой базе нужно указать именно её имя при входе.

## Ручной кластер для разработки

Команды для **cmd.exe** выполняются по одной из папки проекта. Ручной кластер находится в `%TEMP%`; меню использует отдельный кластер в `%LOCALAPPDATA%`.

1. Один раз создать кластер, если папки `%TEMP%\pldebugger-diploma-smoke` ещё нет:

```bat
"C:\Program Files\PostgreSQL\17\bin\initdb.exe" -D "%TEMP%\pldebugger-diploma-smoke" -U debugger_test -A trust --no-instructions
```

`trust` здесь используется только для локального учебного сервера на `127.0.0.1`.

2. Проверить состояние сервера и, если он остановлен, запустить:

```bat
"C:\Program Files\PostgreSQL\17\bin\pg_ctl.exe" -D "%TEMP%\pldebugger-diploma-smoke" status
```

```bat
"C:\Program Files\PostgreSQL\17\bin\pg_ctl.exe" -D "%TEMP%\pldebugger-diploma-smoke" -l "%TEMP%\pldebugger-diploma-smoke.log" -o "-p 15439 -c listen_addresses=127.0.0.1 -c shared_preload_libraries=plugin_debugger" -w start
```

После перезагрузки повторите `status` и при необходимости `start`. `initdb` не нужен, пока папка кластера существует. Если Windows очистила `%TEMP%`, создайте кластер заново.

3. В базе `postgres` создать расширение и учебные функции:

```bat
"C:\Program Files\PostgreSQL\17\bin\psql.exe" -h 127.0.0.1 -p 15439 -U debugger_test -d postgres -X -v ON_ERROR_STOP=1 -c "CREATE EXTENSION IF NOT EXISTS pldbgapi;"
```

```bat
"C:\Program Files\PostgreSQL\17\bin\psql.exe" -h 127.0.0.1 -p 15439 -U debugger_test -d postgres -X -v ON_ERROR_STOP=1 -f ".\debug_smoke.sql"
```

```bat
"C:\Program Files\PostgreSQL\17\bin\psql.exe" -h 127.0.0.1 -p 15439 -U debugger_test -d postgres -X -v ON_ERROR_STOP=1 -f ".\debug_failure.sql"
```

4. Перед запуском CLI-команд с аргументами задать строку подключения **в этом же окне**:

```bat
set "PGDEBUG_DATABASE_URL=host=127.0.0.1 port=15439 user=debugger_test dbname=postgres"
```

`set` действует только до закрытия окна. При новом окне или после перезагрузки команду нужно повторить. Для запуска `.exe` без аргументов эта переменная не нужна.

5. Проверить соединение и запуск отладки:

```bat
cargo run --locked -- info
cargo run --locked -- check "public.debug_smoke(integer)"
cargo run --locked -- interactive-run "public.debug_smoke(integer)" "SELECT public.debug_smoke(3);"
```

`interactive-run` открывает второе соединение и выполняет указанный SQL. На первой остановке введите `n`, затем `c`; ожидаемый результат — `8`. Пример с намеренной ошибкой:

```bat
cargo run --locked -- interactive-run "public.debug_failure(integer)" "SELECT public.debug_failure(3);"
```

После двух команд `n` ожидается ошибка `P0001`. Закрытие канала отладки и результат целевого SQL программа показывает отдельно.

Для вызова из другого клиента выполните в первом окне:

```bat
cargo run --locked -- interactive-line "public.debug_smoke(integer)" 6
```

После сообщения об ожидании выполните во втором окне:

```bat
"C:\Program Files\PostgreSQL\17\bin\psql.exe" -h 127.0.0.1 -p 15439 -U debugger_test -d postgres -X -c "SELECT public.debug_smoke(3);"
```

В первом окне введите `c`; во втором появится `8`. `interactive TARGET` ставит точку на входе. `listen TARGET` автоматически показывает состояние, делает один шаг и продолжает выполнение.

Для остановки ручного кластера после завершения отладки:

```bat
"C:\Program Files\PostgreSQL\17\bin\pg_ctl.exe" -D "%TEMP%\pldebugger-diploma-smoke" -m fast -w stop
```

## Архитектура и интеграция с ORM

Rust открывает соединение с PostgreSQL для управления отладкой. Его серверный процесс — **proxy backend**. Через него программа вызывает `pldbg_create_listener()`, ставит точку и отправляет команды `pldbg_step_over()` или `pldbg_continue()`.

Функцию вызывает другое соединение — **target backend**. Загруженный в PostgreSQL `plugin_debugger` останавливает его на точке и связывает с proxy backend. Поэтому Rust не перехватывает сетевые запросы к порту PostgreSQL. В `src/pldbg.rs` находятся вызовы `pldbgapi`, в `src/main.rs` — меню и команды, в `src/demo.rs` — учебный кластер, в `src/preflight.rs` — проверка функции, в `src/target.rs` — отдельный вызов SQL.

Для будущей ORM уже есть входы `check TARGET` и `interactive-line TARGET LINE`. Python-программа может запустить `.exe` отдельным процессом, дождаться сообщения об установленной точке, вызвать функцию через своё соединение и передать `n` или `c` в стандартный ввод. Текстовый вывод пока рассчитан на человека; машинный протокол и работу с реальной ORM ещё нужно разработать.

## Проверка и ограничения

После изменения кода запустите проверку из PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\verify-demo.ps1
```

Сценарий поднимает временный кластер, проверяет результат `8`, точки остановки, фактическую позицию, проверку тела и ошибку `P0001`, затем останавливает сервер. После `cargo build --release --locked` обновите готовый файл из `target\release\pg-debugger.exe`:

```bat
copy /Y "target\release\pg-debugger.exe" "dist\pg-debugger.exe"
```

При отказе в соединении (`10061`) проверьте порт и `pg_ctl status`. Если кластер не запустился, откройте `%TEMP%\pldebugger-diploma-smoke.log`. Если недоступна `pldbg_get_proxy_info()`, проверьте наличие `pldbgapi` в выбранной базе и загрузку `plugin_debugger` при старте сервера.
